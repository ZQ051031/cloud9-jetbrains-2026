## What actually happened

The initial project and its follow-up UI/realism/documentation work were generated by **Devin, the Cognition AI software engineering agent**, using a command-line development environment. **Devin did not use WebStorm, IntelliJ IDEA, Junie or JetBrains Air for this implementation.** Included run configurations and agent guidelines are preparation for the entrant, not evidence of product use.

The work was split into small verifiable stages:

1. A client-only TypeScript/React/Vite scaffold, seeded fictional telemetry, typed import boundary, pure analytics and Vitest fixtures.
2. Six connected coaching views with shared filter state, original SVG schematics, hand-rolled charts, report exports and a Chrome-over-CDP smoke script.
3. Screenshot-driven correction: distinct map geometry, map/team-specific continuous placements, finer 24×24 density cells, readable 12×12 counts, plural filter labels and contextual anti-strat rules instead of repeating insight sentences.
4. Methodology/provenance disclosure and a portable JetBrains handoff with npm run configurations, conventions and this unfilled session log.

The review loop mattered: screenshots exposed repetitive geometry and planted coordinate anchors that passing unit tests alone did not make visually credible. Focused regression tests now check distinct polygons/features, continuous map/team placements and concrete counter text; CDP checks exercise actual filter changes, downloads, print output, empty slices and mobile layout. This describes software verification, not validation of real VALORANT tactics.

## Why this structure supports JetBrains work

- **WebStorm / IntelliJ IDEA:** a conventional `package.json`, strict TypeScript contracts, focused pure functions and no backend setup make navigation, refactoring and local debugging straightforward. IntelliJ IDEA needs appropriate JavaScript/TypeScript support enabled. `.editorconfig` defines shared formatting; local SDK paths/workspace state stay out of Git.
- **Shared run configurations:** open the repository directory, select the installed **Node 22** interpreter and npm, install dependencies, then use `Cloud9: dev`, `Cloud9: test`, `Cloud9: build`, `Cloud9: preview` and `Cloud9: e2e` from `.idea/runConfigurations/`. Build before preview; leave preview running on 4173 for e2e. Configure `CHROME_PATH` if Chrome is not on PATH. These XML contracts have automated checks, but launching them inside an actual JetBrains IDE still requires the entrant's session.
- **Junie as an AI coding agent:** `.junie/guidelines.md` identifies data provenance, pure-analysis, shared-filter, map-art and testing boundaries. Give Junie one bounded improvement, review its proposed diff in the IDE, demand normal/empty/error tests and reject invented source claims or unsupported tactical certainty.
- **JetBrains Air:** if available to the entrant, delegate a separate bounded task, review the resulting branch/diff and record the actual product/version/session. Availability and supported integrations may vary. This is an intended experiment, not a completed Air session.

No secret is required. Keep bundled `SAMPLE / DEMO DATA — fictional, seeded` visible and do not import/commit private telemetry for workflow screenshots.
